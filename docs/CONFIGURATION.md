# Configuration

RAST is configured by an optional TOML file plus `RAST_*` environment
variables. Everything has a safe default: a fresh installation runs with only
`/etc/rast/rast.toml` generated by the installer.

Configuration is resolved **once at process start**. There is no runtime reload
(RAST does not implement `SIGHUP`): edit the file and run
`systemctl restart rast.service`.

## Precedence and file resolution

Lowest to highest:

1. built-in defaults (`src/config.rs`);
2. `/etc/rast/rast.toml`;
3. `RAST_*` environment variables (including those in `/etc/rast/rast.env`,
   loaded by `rast.service`);
4. explicit CLI flags (`--config`, `--log-level`, `rast serve --bind`).

Config file resolution:

| Order | Source | Behaviour |
| --- | --- | --- |
| 1 | `--config PATH` | Must exist; unreadable/invalid file is a hard error |
| 2 | `RAST_CONFIG` environment variable | Must exist; a hard error if missing |
| 3 | `/etc/rast/rast.toml` | Loaded when present; silently skipped when absent (defaults apply) |

Environment variables that are set but empty are ignored (treated as unset).
Unknown TOML keys are rejected at startup (`deny_unknown_fields`), so a typo
never goes silently unnoticed — the service will fail with the parse error in
`journalctl -u rast.service`.

Validate a configuration at any time without starting the server:

```bash
sudo -u rast rast --config /etc/rast/rast.toml doctor
sudo -u rast rast status          # shows config file, database, health
```

## TOML keys

All keys are optional. The table lists the built-in default and the validation
applied by `src/config.rs`.

| Key | Type | Default | Validation / notes | Env override |
| --- | --- | --- | --- | --- |
| `bind` | string | `"127.0.0.1:8720"` | Parsed as `HOST:PORT` socket address | `RAST_BIND` |
| `public_url` | string | unset | Must start with `http://` or `https://`; trailing `/` stripped | `RAST_PUBLIC_URL` |
| `data_dir` | path | `"/var/lib/rast"` | Must not be empty; must be local storage with SQLite locking | `RAST_DATA_DIR` |
| `storage_dir` | path | `"/srv/rast"` | Must not be empty; should not be inside `data_dir` (warning only) | `RAST_STORAGE_DIR` |
| `trusted_proxies` | array of strings | `[]` | Each entry must be a CIDR (`127.0.0.1/32`, `::1/128`); bare IPs are rejected | `RAST_TRUSTED_PROXIES` (comma separated) |
| `session_ttl_hours` | integer | `168` | 1–8760; absolute cap in code is 30 days | `RAST_SESSION_TTL_HOURS` |
| `monitor_interval_secs` | integer | `5` | 1–300 | `RAST_MONITOR_INTERVAL_SECS` |
| `max_upload_bytes` | integer | `10737418240` (10 GiB) | 1 MiB – 1 TiB | `RAST_MAX_UPLOAD_BYTES` |
| `log_level` | string | `"info"` | `error`, `warn`, `info`, `debug`, `trace`; `RUST_LOG` overrides at runtime | `RAST_LOG_LEVEL` |
| `db_max_connections` | integer | `8` | 1–64 | `RAST_DB_MAX_CONNECTIONS` |
| `worker_socket` | path | `"/run/rast/worker.sock"` | Unix socket path of the worker | `RAST_WORKER_SOCKET` |
| `docker_enabled` | boolean | `false` | Enables the Applications app (needs `rast-worker.service`) | `RAST_DOCKER_ENABLED` |
| `default_quota_bytes` | integer | `21474836480` (20 GiB) | `0` = unlimited; applies to newly created accounts | `RAST_DEFAULT_QUOTA_BYTES` |
| `secure_cookies` | boolean | auto | Auto = `true` when `public_url` starts with `https://` | `RAST_SECURE_COOKIES` |
| `job_concurrency` | integer | `2` | 1–8 | `RAST_JOB_CONCURRENCY` |
| `setup_token_required` | boolean | `false` | Require a one-shot token for the web first-run setup; CLI account creation always works | `RAST_SETUP_TOKEN_REQUIRED` |
| `trust_forwarded_headers` | boolean | auto | Auto = `true` when `trusted_proxies` is non-empty | `RAST_TRUST_FORWARDED_HEADERS` |
| `packages_catalog_url` | string | official catalog (`https://github.com/Enricko/rast-packages/releases/download/catalog/catalog.json`) | `https://` or `file:///`; the detached signature is read from `<url>.sig` | `RAST_PACKAGES_CATALOG_URL` |
| `packages_catalog_keys` | array of strings | `[]` | Extra trusted catalog keys, each `"<key-id>:<base64 Ed25519 public key>"` (32 bytes); invalid entries fail startup. The official key is always trusted | `RAST_PACKAGES_CATALOG_KEYS` (comma separated) |
| `packages_check_interval_minutes` | integer | `360` | 0–10080; `0` disables automatic checks, including the one at start (the refresh button, *Check for updates*, still works) | `RAST_PACKAGES_CHECK_INTERVAL_MINUTES` |
| `packages_shell_path` | bool | `true` | Put the App Center defaults (`<data_dir>/packages/bin`) first on every login shell's PATH through `/etc/profile.d/rast-packages.sh`, and let other users read the installed runtimes (the data directory and package root get only the traverse bit for others). Applied by `sudo rast packages path sync`, which the installer and `rast update` run | `RAST_PACKAGES_SHELL_PATH` |
| `packages_system_wide` | bool | `false` | Also link the official defaults into `/usr/local/bin`, so `sudo`, systemd services, cron (`/etc/crontab`) and scripts run them, not only login shells. A root watcher (`rast-packages-links.path`) re-links after every change. apt files are never changed (`/usr/local/bin` only shadows `/usr/bin`); a command installed there by hand is moved aside to `.rast-displaced.<name>` and put back by *Use the system version* or *Uninstall*. Only the commands of official PHP, Node.js, Go and Python are linked. Root then runs files the `rast` account can change. Needs `packages_shell_path`; applied by `sudo rast packages path sync` | `RAST_PACKAGES_SYSTEM_WIDE` |
| `packages_github_token` | string | unset | Optional token for GitHub API lookups by Install from GitHub (rate limit only; public repositories need no token). Never printed by `rast config` | `RAST_PACKAGES_GITHUB_TOKEN` |

## Environment variables

The canonical example is [`.env.example`](../.env.example). Boolean variables
accept `1`/`true`/`yes`/`on` and `0`/`false`/`no`/`off` (case-insensitive).

| Variable | Equivalent TOML key | Notes |
| --- | --- | --- |
| `RAST_CONFIG` | — | Path to the TOML file (see resolution above) |
| `RAST_BIND` | `bind` | Listen address |
| `RAST_PUBLIC_URL` | `public_url` | Canonical URL, e.g. `https://desktop.example.com` |
| `RAST_DATA_DIR` | `data_dir` | Database, secrets, backups, apps |
| `RAST_STORAGE_DIR` | `storage_dir` | User homes, shared folders, trash |
| `RAST_TRUSTED_PROXIES` | `trusted_proxies` | Comma-separated CIDRs |
| `RAST_TRUST_FORWARDED_HEADERS` | `trust_forwarded_headers` | Explicit override of the auto rule |
| `RAST_SESSION_TTL_HOURS` | `session_ttl_hours` | 1–8760 |
| `RAST_MONITOR_INTERVAL_SECS` | `monitor_interval_secs` | 1–300 |
| `RAST_MAX_UPLOAD_BYTES` | `max_upload_bytes` | 1 MiB – 1 TiB |
| `RAST_LOG_LEVEL` | `log_level` | `RUST_LOG` takes precedence when set |
| `RAST_DB_MAX_CONNECTIONS` | `db_max_connections` | 1–64 |
| `RAST_WORKER_SOCKET` | `worker_socket` | Must match the worker unit's runtime directory |
| `RAST_DOCKER_ENABLED` | `docker_enabled` | `true`/`false` |
| `RAST_DEFAULT_QUOTA_BYTES` | `default_quota_bytes` | New accounts only |
| `RAST_SECURE_COOKIES` | `secure_cookies` | Force the `Secure` cookie flag |
| `RAST_JOB_CONCURRENCY` | `job_concurrency` | 1–8 |
| `RAST_SETUP_TOKEN_REQUIRED` | `setup_token_required` | Harden the web first-run flow |
| `RAST_PACKAGES_CATALOG_URL` | `packages_catalog_url` | App Center catalog (or a local mirror) |
| `RAST_PACKAGES_CATALOG_KEYS` | `packages_catalog_keys` | Comma-separated `<key-id>:<base64>` |
| `RAST_PACKAGES_CHECK_INTERVAL_MINUTES` | `packages_check_interval_minutes` | 0–10080 |
| `RAST_PACKAGES_SHELL_PATH` | `packages_shell_path` | `true`/`false` |
| `RAST_PACKAGES_SYSTEM_WIDE` | `packages_system_wide` | `true`/`false` |
| `RAST_PACKAGES_GITHUB_TOKEN` | `packages_github_token` | Secret; prefer the environment file over the TOML file |

Additional variables that are **not** configuration-file keys:

| Variable | Used by | Meaning |
| --- | --- | --- |
| `RUST_LOG` | tracing subscriber | Direct `EnvFilter` override, e.g. `RUST_LOG=rast=debug,tower_http=info` |
| `RAST_PASSWORD` | CLI password prompts | Non-interactive password for `rast user create-admin` / `reset-password` (prefer `--password-stdin`; an env var is visible to the process list owner) |
| `RAST_WORKER_SOCKET_GROUP` | `rast-worker.service` | Set to `rast` by the unit; the worker chowns its socket to this group so `rast.service` can connect |
| `RAST_WORKER_ALLOWED_UID` | `rast-worker.service` | Numeric uid that may connect to the worker socket (SO_PEERCRED check). The installer writes a drop-in with the `rast` uid; recommended whenever the worker is enabled |
| `RAST_DOCKER_BIN` | `rast-worker.service` | Docker CLI path/name used by the worker (default `docker`); set it for non-standard installations |
| `RAST_GIT_SHA` | build script | Compile-time Git revision embedded in the binary, not user configuration |

### Interpretation rules

* **`public_url`** drives cookie security: when it starts with `https://`,
  `secure_cookies` defaults to `true`. Set it in production even when the
  reverse proxy handles TLS, so that cookies, redirects and links are correct.
* **`trusted_proxies`** enables header forwarding automatically
  (`trust_forwarded_headers` auto-true). Only list proxies you operate:
  `X-Forwarded-For`/`CF-Connecting-IP` from any other peer is ignored and the
  TCP peer address is used instead.
* **`bind`** should stay on `127.0.0.1` when a reverse proxy is in use. Binding
  to `0.0.0.0` is possible but exposes plain HTTP; `rast doctor` warns when the
  bind address is network-reachable and no proxies are configured.
* **`data_dir` vs `storage_dir`** — data is metadata/DB/keys; storage is user
  content (potentially large). They may be the same filesystem, but keep
  `storage_dir` outside `data_dir` so that backups of the data directory do not
  accidentally include user files.
* **`docker_enabled`** alone is not enough: Docker must be installed, the
  worker unit enabled and the `rast-worker` user in the `docker` group.

## Examples

### Minimal (reverse proxy on the same host, TLS terminated by nginx)

`/etc/rast/rast.toml`:

```toml
bind = "127.0.0.1:8720"
public_url = "https://desktop.example.com"
trusted_proxies = ["127.0.0.1/32", "::1/128"]
```

### Cloudflare Tunnel in front (tunnel client on the same host)

```toml
bind = "127.0.0.1:8720"
public_url = "https://desktop.example.com"
# cloudflared connects from loopback and Cloudflare sets CF-Connecting-IP.
trusted_proxies = ["127.0.0.1/32", "::1/128"]
setup_token_required = true
```

### Custom storage volume and smaller uploads

```toml
bind = "127.0.0.1:8720"
public_url = "https://files.example.com"
data_dir = "/var/lib/rast"
storage_dir = "/mnt/data/rast"
trusted_proxies = ["127.0.0.1/32"]
max_upload_bytes = 2147483648   # 2 GiB — keep the proxy limit at or above this
default_quota_bytes = 10737418240
```

The installer writes a matching systemd drop-in (`ReadWritePaths=`) when custom
directories are used; if you move directories by hand, update
`/etc/systemd/system/rast.service.d/10-rast-paths.conf` accordingly.

### Docker / Applications app enabled

```toml
docker_enabled = true
worker_socket = "/run/rast/worker.sock"
```

With the release units, the worker uses the same `RAST_CONFIG`, so no extra
change is needed. Verify with:

```bash
sudo rast worker            # internal, normally run by systemd
systemctl status rast-worker.service
sudo -u rast rast doctor    # checks docker CLI and worker socket
```

### Environment-only configuration

`/etc/rast/rast.env` (mode `0600 root:rast`, loaded by both units):

```bash
RAST_PUBLIC_URL=https://desktop.example.com
RAST_TRUSTED_PROXIES=127.0.0.1/32,::1/128
RAST_LOG_LEVEL=info
RAST_MAX_UPLOAD_BYTES=10737418240
```

Environment variables have higher precedence than the TOML file, which is handy
for secrets-free deployment automation. Do not put secrets in this file — RAST
has no configuration-time secrets beyond the generated `secret.key`.

### App Center mirror signed with your own key

```toml
# Serve a copy of the catalog yourself (or from disk) and sign it with your key.
packages_catalog_url = "file:///srv/mirror/rast-catalog/catalog.json"
packages_catalog_keys = ["my-mirror-2026:BASE64_OF_32_BYTE_ED25519_PUBLIC_KEY"]
packages_check_interval_minutes = 60
```

Installed runtimes live under `<data_dir>/packages/` (`runtimes/<id>/<version>/`,
`runtimes/<id>/current`, `bin/`). With `packages_shell_path` (the default),
`/etc/profile.d/rast-packages.sh` puts `bin/` first on every login shell's PATH,
so a terminal runs the version chosen with *Make default*. A package without a
App Center default has no shim there, and the system's own command is used.
RAST never modifies the operating system's own runtimes (apt packages): it
lists them as *System* and installs updates next to them. `sudo` keeps its own
`secure_path` and services have their own PATH, so they use the system
versions unless `packages_system_wide` links the defaults into
`/usr/local/bin` (which comes first in both). Before turning it on, check that
services and cron jobs that run `php`, `node`, `python3` or `go` by name work
with the App Center build (for example its PHP extensions); per-user
crontabs use `PATH=/usr/bin:/bin` and are not affected. See
[package-center-handoff.md](package-center-handoff.md).

## CLI overrides

Global flags accepted by every subcommand:

| Flag | Meaning |
| --- | --- |
| `--config PATH` | Configuration file to load |
| `--log-level LEVEL` | Override `log_level` for this invocation |

`rast serve --bind ADDR` additionally overrides the listen address without
touching the configuration file (useful for troubleshooting).

## Permissions

| File | Mode | Owner |
| --- | --- | --- |
| `/etc/rast/rast.toml` | `0640` | `root:rast` (the service can read, other users cannot) |
| `/etc/rast/rast.env` | `0600` | `root:rast` if created by the operator |
| `/var/lib/rast/secret.key` | `0600` | `rast:rast`, generated on first start |
| `/var/lib/rast/` | `0750` | `rast:rast` |

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| Service exits with `invalid config file ... unknown field` | TOML key typo (`deny_unknown_fields`) |
| `cannot listen on ...` | Port already used, or `bind` set to an address on a missing interface |
| `invalid trusted proxy CIDR` | Bare IP used; write `127.0.0.1/32` |
| Secure cookies not set behind HTTPS | `public_url` missing or not `https://` |
| Client IPs in audit logs show the proxy | `trusted_proxies` missing/incorrect, or the peer is not in the list |
| Docker features unavailable | `docker_enabled=false`, worker not running, or worker not in `docker` group |
| Upload fails at a fixed size | Reverse-proxy body limit lower than `max_upload_bytes` (nginx `client_max_body_size`, Caddy `request_body`, Cloudflare plan limits) |

See also [INSTALL.md](INSTALL.md) and [OPERATIONS.md](OPERATIONS.md).
